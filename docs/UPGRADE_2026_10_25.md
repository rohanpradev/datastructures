# October 25, 2026: Bun release follow-through

The official [latest stable release](https://github.com/oven-sh/bun/releases/latest)
is **Bun 1.4.4**, released October 22. Both the installed runtime and this
repository already used it after the [October 24 upgrade](./UPGRADE_2026_10_24.md).
This pass reviews the remaining relevant features and adopts them in executable
lessons and everyday commands. The existing runtime/types pins stay at 1.4.4.

## Tooling improvements

| Change                        | Purpose                                                            | Command or location                                 |
| ----------------------------- | ------------------------------------------------------------------ | --------------------------------------------------- |
| Checked server execution      | Stop before startup or a watch restart when TypeScript fails       | `dev`, `ai:dev`, `ai:start`, `course:lab`           |
| Checked tests                 | Check selected tests and their imports before execution            | `bun run test:checked`                              |
| Parallel static gates         | Run independent read-only checks together, then test with coverage | `bun run check` / `check:static`                    |
| Cache-only installation       | Separate dependency downloads from reproducible installation       | `deps:fetch`, then `deps:offline`; Linux/Windows CI |
| Scoped release-age exceptions | Exempt only the named pinned toolchain versions                    | `[install]` in `bunfig.toml`                        |
| Locked database CLI           | Prevent an implicit download when the local CLI is missing         | `bunx --no-install drizzle-kit`                     |
| Runtime requirement           | Declare the minimum version required by formatter and lessons      | `engines.bun` in `package.json`                     |

`bun pm fetch` populates the cache without installing or running scripts. An
offline install requires every locked package needed for that platform to be
cached; an incomplete cache fails instead of silently using the network. CI
retains its OS-specific cache and retry backoff during prefetching.

The standalone TypeScript check remains useful alongside Bun's checker.
`bun --check` still avoids the repository's `check` script name collision.
The optional checked test command is separate from the coverage gate because
`check` already checks the entire configured project before running tests.

## Executable runtime lessons

[WebSocket flow control](../src/node-concepts/bun-runtime/websocket-flow.ts)
demonstrates `pause`, `resume`, and `isPaused` around asynchronous work, bounded
per-client FIFO queues, separate payload/outbound limits, and connection-local
errors. Synchronous throws use the new `error(error, socket)` callback;
asynchronous processing catches its own rejections. Tests cover order,
pause/resume, malformed messages, failure isolation, and closing handshakes.

Both the real-time lab and the general Node/Bun example server now use the
socket-aware error callback. A real-time lab regression test injects a storage
failure during replay and verifies another subscriber still receives events.

[Strict execution probes](../src/node-concepts/bun-runtime/code-generation.ts)
run fixed trusted fixtures under `--disallow-code-generation-from-strings=strict`.
They reject `eval`, `Function`, and JavaScript data URLs, while accepting JSON
data and disk TypeScript modules in source execution. The guide explains the
tighter compiled-executable boundary and the remaining I/O permissions.

`bun run test:bun` now includes these lessons and both SQLite suites, alongside
the existing file, Glob, image, security, shell, process, and modern API tests.
The practice catalog discovers the new exported exercises automatically.

## Release review decisions

The previous pass already adopted `bun fmt`, the new Glob patterns, SQLite
functions/aggregates, readable release age, checker improvements, and registry
retry backoff. This pass keeps those choices and fills the gaps above.

PostgreSQL COPY streams, query cancellation, column transforms, arrays, and SQL
connection settings require an external database and a separate integration
exercise. Yarn Berry migration, recursive publishing, workspace extensions,
proxy TLS settings, and compiled-executable deployment have no active consumer
in this private single-package course. They remain extension topics instead of
unused configuration. Runtime/JSC, stream, Headers, TLS, and protocol fixes
apply through the existing 1.4.4 pin without rewriting callers.

## Verification

Completed locally on Windows with Bun 1.4.4:

- `bun run check` passed formatting, lint, both type checkers, documentation
  links, the practice catalog audit, and **2,631 tests across 66 files**.
- Coverage was **96.25% of functions** and **96.36% of lines**.
- All **308 generated practice targets** passed stub/reference validation;
  the catalog maps all 313 eligible runnable blocks exactly once.
- Checked execution passed all 10 tests in the two new runtime suites.
- Dependency prefetch succeeded. A disposable project with the same package,
  lockfile, and Bun configuration installed **326 packages offline** into an
  initially absent `node_modules` using the populated global cache. This
  verifies a clean install from a warm cache, not cold-cache prefetching.
- `bun audit` found no vulnerabilities among **359 audited packages**.
- The installed Drizzle CLI reports the locked `1.0.0-rc.4` ORM/Kit versions.

Linux execution remains covered by the configured CI matrix and was not run
locally. Dependency versions and `bun.lock` were preserved during this feature
pass; installing the existing graph required no lockfile changes.

Repeat the checks with:

```bash
bun run deps:fetch
bun run deps:offline
bun run check
bun run test:checked src/node-concepts/test/code-generation.test.ts src/node-concepts/test/websocket-flow.test.ts
bun run practice:validate
bun audit
```
